# TradingView webhook bot

Локальный приёмник сигналов TradingView. По умолчанию это бумажная торговля: биржа не вызывается и реальные деньги не используются. Спотовый ордер через ccxt уходит только после явной смены режима.

## Почему вебхук

TradingView не даёт публичного API для выставления ордеров. Браузерная автоматизация и эмуляция приложения нарушают правила сервиса и ломаются без предупреждения. Штатный путь — alert с Webhook URL: TradingView сам отправляет POST на ваш сервер.

## Режимы

| `TRADING_MODE` | Что происходит |
| --- | --- |
| `paper` | Локальная симуляция. Ключи не нужны. В консоли строка `[PAPER] Куплено ...` |
| `testnet` | Рыночный ордер на тестовой сети биржи через ccxt. По умолчанию Binance Spot |
| `live` | Боевой спотовый счёт. Дополнительно нужен `CONFIRM_LIVE=YES_I_UNDERSTAND` |

Покупка тратит `POSITION_SIZE_PCT` свободного депозита в котируемой валюте. Продажа и `close` закрывают только позицию, которую открыл сам бот, и не продают остальные монеты кошелька. Шорты и бессрочные контракты (тикер с `.P`) отклоняются.

Повтор того же тела запроса не исполняется второй раз. Цена из алерта в `testnet` и `live` не становится лимитной ценой: ордер рыночный, а цена сигнала используется для журнала и для проверки, что рынок не ушёл дальше `MAX_DEVIATION_PCT`.

## 1. Установить Python и зависимости

Нужен Python 3.10 или новее. При установке с [python.org](https://www.python.org/downloads/) отметьте **Add python.exe to PATH**.

В PowerShell из папки проекта:

```powershell
cd C:\Users\Asus\tradingview-webhook-bot
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
py app.py --self-test
```

Если команда `py` не находится, используйте `python` вместо `py`.

`ngrok` не ставится через pip. Это отдельная программа, она нужна только чтобы отдать локальный порт наружу.

## 2. Настроить `.env`

Файл `.env` уже создан для бумажного режима. Секрет из примера подходит только для локальной проверки. Перед тем как открывать адрес в интернет, замените `WEBHOOK_SECRET` на длинную случайную строку и вставьте ту же строку в сообщение алерта.

Для Binance Spot Testnet:

1. Откройте [testnet.binance.vision](https://testnet.binance.vision/) и войдите через GitHub.
2. Создайте HMAC-ключ. Включите чтение и спотовую торговлю. Вывод средств не включайте.
3. Впишите ключ и секрет в `.env`.
4. Поставьте `TRADING_MODE=testnet`.

Это ключи тестовой сети, не ключи от основного аккаунта Binance. Для Bybit Testnet поставьте `EXCHANGE_ID=bybit` и возьмите ключи на тестовой сети Bybit.

Боевой режим:

```text
TRADING_MODE=live
CONFIRM_LIVE=YES_I_UNDERSTAND
```

Плюс боевые ключи без права на вывод. Пока нет обеих строк, боевые ордера не отправляются.

## 3. Запустить сервер

```powershell
.\.venv\Scripts\Activate.ps1
py app.py
```

В консоли должно появиться `Режим PAPER` и адрес `http://127.0.0.1:5000/webhook`. Журнал пишется в `bot.log` и в это же окно. Сервер слушает только локальный интерфейс.

Проверка без TradingView, в другом окне PowerShell:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5000/webhook -ContentType "application/json; charset=utf-8" -Body '{"secret":"change-me-please-123","alert_id":"manual-1","action":"buy","ticker":"BINANCE:BTCUSDT","price":"65000","time":"2026-11-06T12:00:00Z"}'
```

Ожидаемая строка сервера:

```text
[PAPER] Куплено 0.00153846 BTC по цене 65000
```

Это 1% от стартовых 10000 USDT по цене 65000. Повтор того же запроса вернёт `duplicate` и второй покупки не будет.

Чтобы сбросить бумажный счёт, остановите сервер и удалите `trades.sqlite3`.

## 4. Открыть порт для TradingView

Оставьте `py app.py` запущенным. Во втором окне:

```powershell
ngrok http 5000
```

Если `ngrok` ещё не установлен: скачайте его с [ngrok.com/download](https://ngrok.com/download), выполните `ngrok config add-authtoken <токен>` и снова `ngrok http 5000`.

Скопируйте адрес HTTPS, который ngrok напечатал, и добавьте путь `/webhook`:

```text
https://ВАШ-АДРЕС.ngrok-free.app/webhook
```

Бесплатный адрес меняется при каждом новом запуске ngrok. После перезапуска обновите URL в алерте.

Если в `bot.log` нет строки `POST /webhook`, а TradingView пишет ошибку доставки, бесплатная страница предупреждения ngrok могла перехватить запрос. Тогда поставьте [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) и запустите:

```powershell
cloudflared tunnel --url http://127.0.0.1:5000
```

В алерт пойдёт выданный адрес `https://....trycloudflare.com/webhook`.

На Render или Railway процесс должен слушать внешний порт: в их панели задайте `HOST=0.0.0.0` и переменные из `.env`. Бесплатный PythonAnywhere для этого бота не подходит: исходящие запросы к бирже там ограничены.

## 5. Настроить алерт TradingView

Вебхуки есть в платных тарифах TradingView, на бесплатном их нет.

1. Откройте график спотовой пары, например `BINANCE:BTCUSDT`.
2. Создайте алерт: кнопка Alert или Alt+A. Для стратегии выберите эту стратегию в условии. Для индикатора сделайте два алерта и вручную пропишите `buy` и `sell`.
3. Откройте вкладку **Notifications**.
4. Включите **Webhook URL** и вставьте адрес из ngrok или cloudflared.
5. В поле **Message** вставьте JSON. Для стратегии:

```json
{
  "secret": "change-me-please-123",
  "alert_id": "{{strategy.order.id}}",
  "action": "{{strategy.order.action}}",
  "ticker": "{{ticker}}",
  "price": "{{close}}",
  "time": "{{timenow}}"
}
```

`{{strategy.order.action}}` подставляется только в алерте стратегии и приходит как `buy` или `sell`. В алерте индикатора напишите `"action": "buy"` или `"action": "sell"` буквально. `sell` и `close` закрывают позицию бота по этому тикеру.

6. Сохраните алерт.
7. Нажмите тест вебхука, если он есть в диалоге. В окне Python должна появиться строка `POST /webhook`, а при подставленных `buy` и цене — строка `[PAPER]`.

Если тест присылает текст `{{strategy.order.action}}` как есть, сервер ответит 400. Это ограничение теста, а не ошибка секретного ключа. Рабочий сигнал стратегия отправит уже с `buy` или `sell`. Пока теста нет, используйте `Invoke-RestMethod` из шага 3.

## Коды ответа

| Ситуация | Код |
| --- | --- |
| Тело не JSON или поля сигнала не разобраны | 400 |
| Секрет отсутствует или неверный | 403 |
| Биржа недоступна, ключ не принят, сеть оборвалась | 500 |
| Ордер исполнен, это повтор, или он отклонён риск-проверкой | 200 |

Секрет в журнал и в базу не записывается. Пока ордер точно не был отправлен, неудачный запрос можно повторить. Если запрос к бирже уже ушёл и завершился ошибкой, тот же самый текст алерта блокируется, чтобы не открыть позицию дважды: смотрите `bot.log` и счёт биржи, затем пришлите новый сигнал.
